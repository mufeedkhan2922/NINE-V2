# NINE V2.9.1 — Provider Reliability Upgrade

V2.9.1 keeps the V2.9 intelligence and safety pipeline intact and hardens the external-data boundary.

## What changed

- Shared in-flight request deduplication for market snapshots and timeframe downloads.
- Shared quote in-flight deduplication.
- Longer quote cache (30 seconds by default).
- Longer snapshot cache (10 seconds by default).
- Local Twelve Data request budget to prevent accidental request storms.
- HTTP 429 detection with cooldown and `Retry-After` handling.
- Expired validated candles are retained during provider cooldown instead of repeatedly retrying every few seconds.
- Backtests reuse an existing validated live dataset when enough candles are already available.
- Backtests fall back to validated cache when the provider is rate-limited.
- Runtime diagnostics now expose provider request count, request budget, cooldown, quote-cache age and last provider error.
- Command Center displays Twelve Data request health.
- Atlas cache lifetimes were increased and Atlas errors are surfaced instead of being hidden behind a generic unavailable state.
- Sentinel and live-trading locks remain unchanged.
- No market/news/calendar data is fabricated.

## Recommended `.env.local`

```env
TWELVE_DATA_API_KEY=YOUR_KEY
FINNHUB_API_KEY=YOUR_KEY
NINE_MARKET_OUTPUTSIZE=240
NINE_BACKTEST_OUTPUTSIZE=500
NINE_BACKTEST_MIN_CANDLES=120
NINE_QUOTE_CACHE_MS=30000
NINE_SNAPSHOT_CACHE_MS=10000
NINE_PROVIDER_MAX_REQUESTS_PER_MINUTE=7
NINE_STREAM_INTERVAL_MS=5000
```

The provider budget is intentionally conservative. If the Twelve Data account has a higher allowance, the value can be increased without changing source code.

## Safety

- Provider cooldown never authorizes trading.
- Missing, stale, suspicious or rate-limited market data keeps execution blocked.
- Sentinel remains an independent hard gate.
- Live broker execution remains hard locked unless the existing explicit confirmation and broker configuration requirements are satisfied.
